建站流水账：从零到上线

2026-10-07 / 建站 / 6 min read

这篇文章整理一下这个站是怎么搭起来的。不是教程，更像流水账——毕竟我也是边搜边做磕磕绊绊过来的，有些坑现在想起来还想笑。

为什么折腾这个站

想有个自己的角落。社交平台的账号说没就没，主页排版永远差强人意。自己的网站就不一样了：想写什么写什么，想放什么放什么，域名后面那一串是自己。

技术选型：不会框架，那就不用

网上的教程开口就是 React Vue 三件套，我看两集就困。我的需求其实很简单：几个页面、一个列表、能留言。纯 HTML + CSS + JS 完全够用——后来证明这个决定无比正确：没有构建、没有依赖地狱，坏了打开文件就能看。

托管选了 GitHub Pages：免费、自带 HTTPS、git push 之后一两分钟自动部署。对个人小站来说，这就是天花板了。

我的流程：写 → 看 → 存 → 发

  1. 本地改文件，用 python -m http.server 起个服务实时看
  2. 浏览器 F12 当显微镜，手机视图也要过一遍
  3. 满意了 git commit——小步提交，每一步都能后悔
  4. git push，等 Pages 自动上线

听着平淡，但「每一步都能后悔」这条救过我无数次。

网站不是做完的，是养出来的。

踩过的坑（都是真金白银的时间）

字体：随手放的字体全家桶 61MB，首屏慢到能泡杯咖啡。后来用 fontTools 做子集化，只保留用到的字，砍到 3.3MB。音乐：播放器每次加载都预载整首歌（2~9MB），改成点播放才加载。看板娘：可爱是可爱，满帧渲染 GPU 直冒烟，限帧 24 之后世界都清净了。缓存：改了代码浏览器死活不认新文件，给资源引用加版本号 ?v=4，一劳永逸。还有 Chrome 卡顿，最后发现是硬件加速没开——就这么一个开关。

心得

别急着上框架，先想清楚要什么；小步提交，出问题知道退回哪一步；改动先本地过目，确认了再上线（这条是血泪教训）；AI 是很好的结对搭子——它写代码我拍板，效率翻倍，但拍板的责任在人。

这个站还会慢慢养下去。下一篇见。
